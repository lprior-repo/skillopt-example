02

Workflow

One supported path keeps dataset generation, rollout execution, and evidence aligned.

  1. GenerateCreate deterministic split data under `data/holzman_rust_aggressive`.
  2. EvaluateRun candidate skill bundles through `scripts/run_holzman_candidate_eval.py`.
  3. RecordPersist `run_metadata.json`, bundle hashes, summaries, and raw artifacts.
  4. PromoteAccept only full `val,test` hard `1.0` runs with `non_promotable: false`.
03

MiniMax M3 with thinking

The OpenCode rollout passes the configured model and variant to every task.

env:
  review_model: minimax-coding-plan/MiniMax-M3
  repair_model: minimax-coding-plan/MiniMax-M3
  opencode_variant: thinking
  opencode_show_thinking: true

The evaluator writes these effective settings into `run_metadata.json`, along with candidate, config, and dataset manifest hashes.

04

Promotion gate

Promotion is designed to fail closed. A convenient rerun is never promoted by accident.

Eligible

Full `val,test`, `--kind all`, no `--ids`, `limit: 0`, checked-in split dir, hard `1.0` on both splits.

Non-promotable

Targeted IDs, partial split sets, review-only/repair-only runs, alternate raw data paths, or any hard failure.

Evidence

Keep `run_metadata.json`, `bundle_hashes.json`, per-split summaries, and raw prediction artifacts together.

Skill bundles

Each skill bundle is self-contained and discoverable by the training harness.

skills/holzman-rust/
  SKILL.md
  rubric.json
  prompt.md
  tasks.jsonl
  eval.py
  config.json

Use `uv run skillopt-train list --skills-root skills` to discover bundles and `uv run skillopt-train run holzman-rust --steps 4` to evolve one locally.

06

Troubleshooting

Why did my run exit `2`?

The run wrote artifacts, but it was not promotion eligible. Check `promotion_reason` in `run_metadata.json`.

Why did my run fail before OpenCode launched?

The evaluator rejects unsupported configs before rollout. Check `split_mode`, `split_dir`, `data_path`, and `limit`.

Where do model settings show up?

`run_metadata.json` records `review_model`, `repair_model`, `opencode_variant`, and `opencode_show_thinking`.
